# Moyai / Substrate cluster: rebuild and daily use

Moyai is the optional sandbox backend. The chat apps call it through the relay on Netcup (`gca-relay`,
see `relay/`). When the GKE cluster is down the chat shows Moyai as offline and routes to the Default sandbox.

## States
| State | How to get there | Cost |
|---|---|---|
| Cluster deleted, data kept (now) | - | about Rs29/day (static IP, 3 disks, images, snapshots) |
| Cluster up | `gcp-setup.sh` (you run it), then `moyai-rebuild.sh` | about Rs36/hour |
| Cluster parked (nodes at 0) | `moyai-down.sh` | about Rs60-75/day |
| Back from parked | `moyai-up.sh` | |

## Rebuild after a delete
1. YOU run `~/Projects/moyai-stack/gcp-setup.sh` (creates the cluster and IAM grants; auto mode cannot).
2. `./moyai-rebuild.sh` (or one stage at a time: labels pv substrate litellm edge workers netcup verify).
3. Test: open a chat, tick "Force Moyai", ask for an app, watch the sandbox line say Moyai.
4. End of day: `~/Projects/moyai-stack/moyai-down.sh`.

## Known risks (first untested rebuild)
- Secrets were never exported: `litellm-secrets` is recreated and the old role password is reset inside the DB pod
  (local socket is trust-auth). Moyai's LiteLLM virtual key lives in the retained DB; if it no longer authenticates,
  create a new virtual key with the new master key and update `moyai.env` on Netcup.
- The Substrate Postgres uses `POSTGRES_HOST_AUTH_METHOD=trust`, so the retained disk needs no password.
- New JWT/CA pool secrets are generated by the installer; sandboxes from before the delete are not resumable.
- If the verify stage says the ActorTemplate is missing, recreate it from `k8s/moyai-template.json` with the new
  worker image digest, as in the original build.
